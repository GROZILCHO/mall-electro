# Mall Electro I18N Route Parity Audit

Last updated: 2026-06-29
Task: ME-I18N-02
Mode: Audit only

## Scope

This audit compares the current runtime routes, SEO route configuration, and typed i18n route foundation before any multilingual runtime wiring.

Implementation files were inspected only. No source code, routing, SEO behavior, prerender behavior, or EN/RO public output was changed.

## Files Compared

- `App.tsx`
- `seo/seoConfig.ts`
- `scripts/prerender.mjs`
- `data/i18n/routes.ts`
- `data/i18n/locales.ts`
- `data/i18n/types.ts`

## Current Runtime Route Model

`App.tsx` currently exposes Bulgarian routes only.

- Root `/` redirects to `/bg/`.
- Legacy unprefixed routes redirect to Bulgarian localized routes.
- Active public pages are under `/bg`.
- `/404` is the only standalone utility route.
- No `/en` or `/ro` route is wired in `App.tsx`.

The runtime route inventory includes `/bg` and `/bg/` as the same home page target for normalization. The i18n foundation uses `/bg/` as the canonical home path.

## Current SEO Route Model

`seo/seoConfig.ts` currently contains 28 SEO route entries.

- All SEO route paths are Bulgarian or `/404`.
- No SEO route path starts with `/en` or `/ro`.
- Sitemap/prerender source is still `seoRoutes`.
- `scripts/prerender.mjs` prerenders exactly `seoRoutes.length` routes.

## Current I18N Route Model

`data/i18n/routes.ts` defines route maps for `bg`, `en`, and `ro`.

- `bg` routes are marked `active`.
- `en` routes are marked `planned`.
- `ro` routes are marked `planned`.
- EN/RO route data is not imported by runtime routing, SEO config, or prerender output.

`data/i18n/locales.ts` marks only Bulgarian as public.

- `bg.isPublic = true`
- `en.isPublic = false`
- `ro.isPublic = false`

## Parity Results

### App Route Parity: PASS

All active Bulgarian canonical routes in `App.tsx` are represented in the Bulgarian i18n route map after trailing-slash normalization.

Notes:

- `/bg` and `/bg/` both resolve to the home page in runtime handling.
- The i18n map keeps `/bg/` as the canonical home route.
- Legacy redirects are intentionally not modeled as canonical route keys.

### SEO Route Parity: PASS

All paths in `seoRoutes` are represented in the Bulgarian i18n route map after trailing-slash normalization.

Notes:

- SEO uses `BG_HOME_PATH = "/bg"` while i18n uses `"/bg/"`.
- This is a normalization difference, not a route gap.
- SEO route keys and i18n route keys differ for some service pages, but the paths match.

### BG Mapping Completeness: PASS

The Bulgarian i18n map contains the complete canonical route set:

- Home
- Services overview
- 6 service detail pages
- Solutions overview
- 6 solution detail pages
- About
- Industries overview
- 6 industry detail pages
- Contact
- 3 legal pages
- 404

### EN/RO Inactive Status: PASS

EN and RO routes are present only as planned route data.

- No EN/RO routes are wired in `App.tsx`.
- No EN/RO routes are present in `seoRoutes`.
- No EN/RO routes are generated by `scripts/prerender.mjs` because prerender still depends only on `seoRoutes`.

## Non-Blocking Issues Found

- Service route key names differ between runtime/SEO and i18n. Example: `electricPanels` in `App.tsx` and `seoConfig.ts` maps to `serviceElectricPanels` in `data/i18n/routes.ts`.
- Home route normalization differs between SEO (`/bg`) and i18n (`/bg/`), but both resolve to the same canonical URL behavior.
- EN/RO slugs are architectural placeholders and must remain inactive until translation and route activation are explicitly approved.
- Some localized display labels and SEO text appear garbled in terminal output, likely due to encoding display or existing mojibake. This is outside ME-I18N-02 route parity scope and should be handled in a separate content/encoding cleanup task.

## Audit Conclusion

The typed i18n route foundation is route-parity safe for the current Bulgarian production site.

No EN/RO output is exposed by the current runtime, SEO, or prerender setup.

Recommendation: proceed to ME-I18N-03.
