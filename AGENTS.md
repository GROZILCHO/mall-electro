# Mall Electro Agent Instructions

This file defines stable working rules for AI coding agents working on the Mall Electro React/Vite project. It complements `PROJECT_RULES.md` and must be followed unless the project owner explicitly gives a newer instruction.

## 1. Project Identity

Mall Electro is an industrial B2B website for electrical systems, electrical panels, industrial electrical installations, cable routes, automation, engineering execution and service support.

The site should communicate a practical, reliable, premium engineering feel for industrial clients. It is not a generic marketing site and should not drift into decorative, consumer-style or SaaS-style visuals.

## 2. Approved Visual Baseline

- The Home page is approved as the primary visual baseline.
- The Industries page is approved as the direction for industrial visual density and content presentation.
- Heavy sections with real images, technical cards, industrial panels and premium engineering visuals must be preserved.
- Do not simplify the design character without explicit approval.
- Do not redesign Home or Industries unless explicitly requested.
- Do not remove the image/card-heavy character of existing sections.
- When extending the site, reuse the existing page rhythm, visual weight and component style.

## 3. Design System Rules

Follow `PROJECT_RULES.md` as the source of truth for design decisions.

Use only approved colors:

- `--brand-blue: #4A90E2`
- `--brand-dark: #1C2A39`
- `--brand-orange: #FF6D2E`
- `--gray-100: #F5F7FA`
- `--gray-200: #E7EDF5`
- `--gray-900: #111`
- `--white: #fff`

Component and styling rules:

- Reuse existing components before creating new ones.
- Use existing layout and UI components such as `Button`, `Badge`, `Card`, `FadeIn`, `GridContainer`, `PageHero`, `IndustryCard`, `ServiceTile`, `Process`, `ContactForm`, `LogoStrip` and `Testimonials`.
- Do not create new visual patterns without approval.
- Do not create new color tokens.
- Do not add new button variants.
- Do not use decorative fonts.
- Do not introduce random spacing or irregular grids.
- Use approved section rhythm and spacing from `PROJECT_RULES.md`.
- Avoid inline CSS. Move styles to CSS classes unless inline style is unavoidable for a narrow technical reason.
- Preserve the industrial, engineering, premium minimal style.
- Do not modify Navbar, Footer or Layout unless the task explicitly asks for it.

## 4. SEO Rules

SEO is configured through:

- `seo/seoConfig.ts`
- `components/seo/SEO.tsx`
- `entry-server.tsx`
- `scripts/prerender.mjs`

Rules:

- Every route must have a unique SEO title and description.
- Canonical URLs must use trailing slash format, for example `https://mallelectro.com/services/`.
- Open Graph tags must be maintained.
- Twitter card tags must be maintained.
- JSON-LD/schema output must be maintained where relevant.
- Production SEO deployment must use the full prerender build: `npm run build`.
- Do not use `npm run build:client` for SEO production deployment because it skips prerendered HTML generation.
- Do not create thin SEO pages.
- Every future SEO page must contain real useful content, not keyword stuffing.
- Future pages should be added to `seoRoutes` and included in prerender output when they become public routes.
- Keep `robots.txt` and `sitemap.xml` generated by the prerender workflow in sync with public routes.

- `/industries/agro`

Route rules:

- Do not add links to routes unless the route exists or is created in the same task.
- Do not remove future SEO-relevant links by default. First report them as missing planned pages.
- If adding a route, update routing, SEO config, prerender route list and sitemap output together.
- Keep overview pages useful and navigable, but do not overload them with long text.
- Add a 404 route/page before expanding the route tree heavily.

## 6. Content Rules

- Content must be concise and useful.
- Avoid long text blocks.
- Avoid generic marketing fluff.
- Use practical B2B industrial language.
- Use terms relevant to electrical panels, industrial electrical installations, automation, cable routes, low voltage systems, HVP, grain processing, logistics bases and production facilities.
- Service cards should have short descriptions and up to 3 bullets.
- Overview pages must be useful but not overloaded.
- Approved content and layout patterns from the existing Home and Industries pages can be reused as baseline.
- Do not keyword-stuff.
- Keep CTA copy direct and practical.

## 7. Workflow Rules

Every task should follow this sequence:

1. Analysis
2. Plan
3. Implementation
4. Diff Summary
5. Risks/Assumptions

AI agents must:

- Change only requested files.
- Avoid large refactors without approval.
- Preserve existing approved style.
- Report assumptions.
- Report broken or suspicious links.
- Report SEO implications.
- Keep edits scoped to the requested task.
- Avoid visual redesign unless explicitly asked.
- Prefer small, reviewable changes over broad rewrites.
- Run relevant checks when possible, especially `npm run build` for SEO/prerender changes.

## 8. Immediate Project Priorities

1. Stabilize overview pages: Home, Services, About, Industries, Contact.
2. Add 404 route/page.
3. Sync fallback SEO in `index.html`.
4. Build Services as an SEO hub.
5. Build About as a trust page.
6. Add service detail pages gradually.
7. Add industry detail pages gradually.
8. Improve internal linking and footer links after pages exist.

## Notes For Agents

- `PROJECT_RULES.md` is strict. If an existing component currently contains variants or styling that go beyond `PROJECT_RULES.md`, do not expand that drift.
- Existing approved pages may contain rich photographic/industrial imagery. Preserve this because Home and Industries are approved baselines.
- If a task conflicts with these instructions, stop and report the conflict before making broad changes.
